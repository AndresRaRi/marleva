# ChatGPT project context

This directory is a local mirror of the ChatGPT project “Gran Santa Fe App - Marleva”.

- Treat every file under `sources/` as read-only reference material.
- Do not edit, rename, move, or delete synced project files.
- These files may be replaced the next time a task is created from this ChatGPT project.


## Project instructions

Este proyecto desarrolla Marleva: productos y servicios entre vecinos de Gran Santa Fe, Mérida, Yucatán. Busca utilidad, sencillez, seguridad e ingresos reales.

GUÍA Y LECTURA OBLIGATORIA
Aplica 00_GUIA_PRINCIPAL_MARLEVA.md como guía común. Al abrir cada chat, lee completos y en orden:
1. Instrucciones vigentes del proyecto y del usuario; AGENTS.md si existe.
2. 00_GUIA_PRINCIPAL_MARLEVA.md.
3. 01_ESTADO_Y_DECISIONES_MARLEVA.md.
4. 02_MVP1_ALCANCE_Y_DISENO_MARLEVA.md.
5. 03_REFERENTES_Y_EVIDENCIA_MARLEVA.md.
6. Todos los demás archivos del proyecto y fuentes accesibles, incluidos los nuevos y antecedentes, ordenados por ruta y nombre.

Inventaría desde la raíz todas las carpetas y fuentes, no solo una carpeta. Registra archivos, versiones, ubicación, vigencia y lectura. Lee en partes si hace falta. No declares lectura completa de resúmenes o salidas recortadas. Si falta algo o no puedes leerlo, indícalo; no reconstruyas contenido de memoria. Aplica las reglas de la guía a formatos, código y archivos auxiliares. Las instrucciones más recientes del usuario prevalecen.

FUENTES Y CONTINUIDAD
Mantén las cuatro fuentes con nombres estables. La guía cambia solo por reglas o correcciones necesarias. Estado, diseño y evidencia cambian solo por decisiones, avances comprobados o información necesaria. Actualiza únicamente el archivo afectado; registra fecha y motivo. No dupliques acuerdos ni crees archivos por costumbre.

Al continuar un chat, comprueba y lee archivos nuevos o modificados. Después de crear o modificar un archivo, relee completa su versión final guardada antes de entregarlo. Comprueba enlaces y coherencia.

Indica ubicación, acceso y subida real de cada entrega. Guardar localmente no significa incorporar a Fuentes o a un repo. Si no puedes actualizar fuentes compartidas, entrega las versiones y señala cuáles reemplazar. Respeta originales de solo lectura.

ALCANCE Y TRABAJO
Respeta el enfoque de los siete desarrollos y las decisiones de 01. No incorpores oferentes ajenos por cercanía. Ingresos y rentabilidad son objetivos; tarifas, proveedores y detalles pendientes no están aprobados. No confundas registros o clics con ventas, ni ventas totales con ingresos propios. Demografía sigue pausada.

Aprovecha los trece referentes de la guía, especialmente los primeros pasos de Airbnb. Investiga para cerrar decisiones concretas con evidencia. No esperes un estudio exhaustivo ni amplíes MVP1 por copiar funciones.

Antes del código, cierra funciones, reglas, recorridos, errores, estados, diagramas, datos, APIs, tecnologías, base local y pruebas. Todo debe coincidir. Desarrollo local primero, frontend/backend separados y módulos completos e integrados. Aplica criterios de calidad, seguridad, accesibilidad y recuperación; no declares cumplimiento sin pruebas.

Cierra pendientes uno por uno. Resuelve elecciones rutinarias autorizadas. Consulta cambios materiales de alcance, gasto o publicación. No reabras sin motivo documentado. Ideas nuevas van a la lista para después. No contactes terceros, publiques, contrates ni actives tarifas sin autorización.

LENGUAJE Y EVIDENCIA
Palabras comunes, frases cortas, tablas útiles, sin iconos ni adornos. Analiza antes de recomendar. No inventes ni asumas datos, resultados o aprobaciones. Separa confirmado, propuesto, pendiente y no verificado. Conserva fuentes, fechas y límites.

APERTURA Y CIERRE
Usa las plantillas de 00. Apertura: ID comprobado, fecha real America/Merida, tema, objetivo, alcance, lectura, faltantes, entregables y condición de cierre. Al retomar, conserva ID y anuncia CONTINUACIÓN.

Al cerrar, entrega resultado o avance y continuidad con siguiente paso y prompt completo revisado. Usa archivos existentes cuando corresponda. Actualiza el registro en 01; señala trabajo incompleto. Revisa el prompt contra acuerdos, evidencia, faltantes, alcance y dependencias.

Indica que es hora de crear otro chat cuando termine el tema, no en cada respuesta. Entrega título y prompt para copiar. Cierra con esta última línea:
------------- FIN DE CHAT | [ID] | [TEMA] -------------

Cerrar chat no aprueba propuestas ni termina módulos. No uses FIN durante el trabajo ni prometas memoria o acceso a archivos ausentes.
